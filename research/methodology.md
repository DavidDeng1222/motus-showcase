# Research methodology

Motus uses a small, repeatable loop:

1. **Choose a concrete observable.** A claim must be visible in ordinary source video or tied to a documented device API.
2. **Bind every result to source time.** Derived body, racket and 3D presentations retain the frame or timestamp needed for review.
3. **Separate record from presentation.** Native observations remain unchanged. A bounded display layer may improve continuity without increasing recognition counts.
4. **Create adversarial checks.** Tests cover damaged timestamps, person changes, low-confidence joints, discontinuities, stale callbacks and invalid source bindings.
5. **Keep failure evidence.** Rejected candidates, failed builds and abandoned higher-coverage variants remain in an append-only private archive.
6. **Publish the narrow claim.** Test counts, display coverage and recognition evidence are described as different measurements.

## Why this matters

A polished animation can look correct while being sourced from the wrong athlete or an unsupported gap. Motus therefore treats provenance, continuity and measurement as separate questions:

- **Provenance:** Which source frame and athlete produced this result?
- **Continuity:** Can the interface present a stable replay across supported moments?
- **Measurement:** Which values came from native observations, and which came from display-only geometry?

This structure makes an error easier to find and makes a successful result easier to defend.
